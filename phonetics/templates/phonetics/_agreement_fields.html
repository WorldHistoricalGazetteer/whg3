{% comment %} The contribution-agreement fields, rendered from the form. ⚠ ONE definition, two surfaces (the page and the modal). Do not hand-write these inputs again: the labels previously existed in three places, the form's own `accept` label was rendered nowhere, and the two template copies had already drifted from it. A consent checkbox whose recorded wording differs from the wording on screen is worse than no record. **Asked in three stages, narrowing.** Attribution is a decision, so it is asked as a question with no option pre-selected, and each answer only opens what it makes relevant: 1. Do you want to be credited? — always shown, nothing pre-selected 2. …under what name, with which ORCiD? — only if yes, prefilled for approval 3. …shown publicly? — only once a name has been typed The disclosure is **CSS, not JavaScript** (see phonetics.css). The modal fetches this fragment over AJAX long after DOMContentLoaded, so a script bound at page load would never see it; and if `:has()` is unsupported the whole progressive rule is skipped and every field is simply visible, which is a safe fallback rather than a broken form. ⚠ Because the disclosure is presentational, the server does not trust it: AgreementForm.clean() normalises the later answers to the first one. A field someone never saw cannot end up in their consent record. `accept` is absent on CreditForm (revising your credit is not re-agreeing), so it is guarded rather than assumed. {% endcomment %}
